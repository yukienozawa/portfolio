## 1. 画面一覧

### 🌐 公開ページ（誰でも閲覧可能）
1. **トップページ (`/`)**: ポートフォリオの顔となるエントランス。
2. **プロフィール (`/profile`)**: 経歴や自己紹介の動的表示。
3. **実績 (`/works`)**: データベースから取得した実績一覧のカード型UI表示。
4. **スキル (`/skills`)**: 習得スキルのレーティングまたは一覧表示。
5. **コンタクト (`/contact`)**: 問い合わせ送信フォーム。

### 🔒 管理画面（要ログイン・Admin権限）
6. **管理者ダッシュボード (`/admin`)**: コンテンツ管理の拠点。
7. **実績登録・編集フォーム (`/admin/edit`)**: 各種文言や実績テキストのCRUD操作、および実績に紐づく画像のバイナリ/Base64送信UI（アップローダーコンポーネント内包）。

### 共通コンポーネント（全ページ適用）
- **共通ナビゲーション（PageNav）**: すべての公開ページに適用。当初Skillsページにのみ実装が抜けていたが、追加済み。
- **共通フッター（Footer）**: 全ページ共通のフッターコンポーネントを新規作成し、5つの公開ページすべてに適用済み。トップページのみフッターがある、という古い状態は解消されている。

## 2. UIの役割と入力項目

### 問い合わせフォーム (`/contact`)
- **役割**: ユーザーからのメッセージを受け付け、バックエンド経由でDB保存およびGmail転送を行う。お問い合わせ機能自体のON/OFF切り替え（`ContactSetting`）に対応しており、無効化されている場合はフォーム自体を表示しない、または送信を拒否する。
- **入力項目**（`api.md`のリクエストボディと統一済み）:
  * お名前 (`name`): テキスト入力、必須、100文字以内
  * メールアドレス (`email`): メール形式、必須
  * 本文 (`message`): テキストエリア、必須、2000文字以内

### 実績登録・更新フォーム (`/admin/edit`)
- **役割**: 管理者が実績コンテンツを更新する。
- **入力項目**:
  * 実績名 (`achievementTitle`): テキスト入力、必須
  * 説明文 (`description`): テキストエリア、必須
  * 画像 (`imageData`): ファイルアップローダー（Base64文字列またはBlobへの変換処理をフロント側で実施、上限2MB）

## 3. 状態管理・ルーティング保護概要
- **ルーティング保護**: フロントエンドの **`front/src/proxy.ts`**（Next.js 16における`middleware.ts`の後継）でFirebase Authのセッションをチェック。未認証時はリダイレクトせず、**404ページ（NotFoundコンポーネント）** をダイレクトに描画して管理画面の存在自体を隠蔽します。バックエンド側の`verifySessionCookie`と合わせた二重の認可構造となっている（詳細は`overview.md`3章参照）。
- **フロントエンド状態管理**: 基本的に Server Components によるデータ取得を主軸とし、フォームの入力値制御など局所的な状態管理には React の `useState` などの最小限のHooksを利用（複雑なグローバルストアはMVPフェーズでは導入しない）。
