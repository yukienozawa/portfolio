# テスト戦略・規約書（Test Strategy）

## 1. テストツールと役割分担
* **Unit Test: Vitest**
  * ロジックや共通関数の検証
  * フロント側は画面ファイルのすぐ横（コロケーション）に配置
* **API Test: Supertest / Vitest**
  * `api/src/__tests__/` 内に集約
  * `app.ts`（アプリ定義）のみを読み込み、サーバー起動（listen）なしで高速実行
  * テスト用DB（MySQL）に実際に関数を走らせ、Prisma経由の読み書きを検証
* **E2E Test: Cypress**
  * Dockerコンテナ間でフロントとバックエンドを実際に合流させて実行
  * ブラウザ操作を模し、入力・サジェスト選択・保存・履歴反映の連動を検証

## 2. 命名規則と配置ルール
* **拡張子**
  * ロジック・APIテスト: `*.test.ts`
  * 画面（JSX）を含むテスト: `*.test.tsx`
* **配置場所**
  * バックエンド: `api/src/__tests__/` に集約
  * フロントエンド: 画面ファイル本体のすぐ横（同フォルダ内）に並べる

## 3. 厳格なバリデーションテスト項目（400弾き）
* **収支タイプ（type）**: `0`・`1` 以外の数値（例: `9`）で確実に400エラーになるか
* **金額（amount）**: 文字列や負の数で確実に弾かれるか
* **備考（memo）**: 仕様通り **31文字以上** で確実に `400 BAD_REQUEST` になるか
